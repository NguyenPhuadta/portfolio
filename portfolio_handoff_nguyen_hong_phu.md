## 9. SmartHue — Survey Trigger Case

This is a strong **mini-case**, not necessarily the flagship.

### Goal
Identify the right moment to show an in-app survey about light-control experience without blocking core usage.

### Final trigger logic
Survey:
- Only for **paying users**
- Only in **Session 2**
- Trigger after the **second light-control action**
- Qualifying actions:
  - On / Off
  - Brightness
  - Color
- If the user leaves before trigger:
  - **No fallback to Session 3**

### Problem constraints
- Survey risks interrupting core light-control experience.
- Brightness/color may be multi-step interactions.
- System could not reliably use idle-time detection after action.
- New tracking events might not be available.
- Post-launch analysis needed to rely on existing GA4 tracking where possible.

### Strong narrative
1. Business needs feedback from paying users.
2. Survey itself creates UX risk.
3. Analyze behavior / action patterns.
4. Compare possible triggers.
5. Consider technical constraints.
6. Choose measurable trigger logic.
7. Define post-launch metrics.
8. Monitor whether survey damages core behavior.

### Recommended title
**Finding the Right Moment to Ask**

Alternative:
**Designing a Data-Informed Survey Trigger Without Blocking Core Usage**

### Why this case matters for Optimizely
Shows:
- Experiment thinking
- Behavioral reasoning
- Trade-offs
- Measurement planning
- Data-informed product decisions
- UX risk management

## 23. Known Tracking / Analytics Context

### SmartHue event naming convention
`action_name_type`

Where:
- `action` = behavior verb
- `name` = target object/content
- `type` = UI/component type being measured

Important:
- `type` is **not state**.

Examples:
- `view_home_screen`

### Reuse rule
Same behavior across screens should reuse the same event where possible.

Differentiate using parameters such as:
- source_screen
- screen_name

### Context fields
- `screen_name` = semantic screen context
- `screen_id` = specific UI/version

### Connection
`connection_type` intentionally groups:
- connection method
- ecosystem / brand

This can support an analytics / system-thinking case if needed.
